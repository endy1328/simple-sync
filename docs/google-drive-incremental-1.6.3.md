# Google Drive 반복 동기화 설계 및 검증 — 1.6.3

작성일: 2026-11-12

## 목적

한 번 동기화한 후 하루 10개 이하의 파일이 바뀌는 사용 환경에서, 매 실행마다 전체 Drive 폴더를 조회하고 모든 PC 파일의 내용을 읽는 비용을 줄인다. 파일 전송의 소스 우선 규칙과 미러링 영구 삭제 보호를 유지한다.

## Drive 목록 저장과 변경 기록

- 계정 ID, 선택 루트, 원본/Google 문서 내보내기 보기, 필터를 범위로 삼아 목록과 변경 커서를 Windows 사용자 데이터 폴더 `SimpleSync/DriveInventory`에 저장한다. 인증 토큰은 포함하지 않는다.
- 최초 목록 검사 **이전**에 `changes.getStartPageToken`을 호출한다. 검사 도중 생긴 변경은 다음 실행의 `changes.list`에서 재생한다.
- 반복 실행은 선택 루트를 새로 확인하고 모든 변경 페이지를 끝까지 받은 뒤, 바뀐 파일의 이전·현재 상위 폴더만 다시 조회한다. 계정의 다른 위치 변경은 저장된 루트 범위와 대조하여 제외한다.
- 알려진 폴더의 이동·이름 변경·삭제 또는 범위 안으로 들어오는 폴더 변경은 전체 검사로 복구한다. 경로 재구성에 대한 잘못된 추정을 피하기 위한 의도적인 정책이다.
- 필터·계정·루트·보기 변경, 유효하지 않은 커서, 불완전하거나 잘못된 변경 응답, 손상된 저장 파일, 7일이 지난 전체 검사 기준 정보는 전체 검사로 복구한다. 권한·통신 오류는 이전 정보를 신뢰하는 대신 작업 실패로 처리한다.
- 데이터와 커서를 하나의 체크섬 포함 파일로 원자적으로 교체한다. 전체 검사가 마지막으로 성공한 시각을 유지하므로 반복 실행이 7일 검증을 계속 미루지 않는다.
- 파일 읽기·쓰기·삭제 직전의 신원, 상위 경로, 동명 항목 검사와 업로드 해시 검증은 계속 새 원격 응답으로 수행한다.

## PC 해시 재사용

- 로컬 NTFS에서 볼륨·파일 ID, NTFS ChangeTime, 최종 쓰기 시각과 크기를 열린 파일 핸들로 확인한다. 식별 정보가 모두 같을 때만 저장한 MD5를 재사용한다. 크기·최종 수정시각만으로 재사용하지 않는다.
- 파일 목록은 매번 열거하므로 생성·삭제·이름 변경을 반영한다. 내용이 바뀌었는데 수정시각을 되돌린 경우에도 NTFS ChangeTime으로 다시 해시한다.
- NTFS가 아닌 파일 시스템, 네트워크 경로, 신원 조회 실패 등 불확실한 경우에는 내용 전체를 읽는 기존 검사로 돌아간다.
- 7일마다 전체 내용 해시를 검증하며, 저장 파일 체크섬·형식에 문제가 있어도 다시 검사한다. 캐시 저장 실패는 정상적인 파일 동기화를 막지 않는다.
- 이 최적화는 Drive와 동기화하는 로컬 끝점에 적용한다. 로컬 간 동기화의 기본 검사 방식은 유지한다.

## 소스 우선 및 미러링

Drive에서만 파일이 수정되거나 삭제되어도 변경 기록으로 대상 목록을 갱신하므로, PC 소스가 그대로인 경우 해당 파일을 다시 올려 복원한다. 역방향도 Drive의 변경된 원본 버전과 해시를 반영한다.

미러링의 삭제 후보가 있을 때는 소스를 저장된 해시나 Drive 목록에 의존하지 않고 다시 전체 검사한다. 처음 목록과 다르거나 작업이 실패·취소되면 삭제하지 않는다. 삭제 후보가 없는 반복 동기화에서는 불필요한 두 번째 소스 전체 검사를 생략한다.

## 모의 검증 결과

기존 Drive HTTP 모의 서버와 실제 동기화 엔진을 사용했다. 이미 내용이 일치하는 454개 폴더·2,070개 3바이트 MD 파일을 준비한 뒤 실행했다. Copy와 Mirror에서 동일한 결과를 확인했다. Mirror 시나리오에는 삭제 후보가 없다.

| 시나리오 | 전체 Drive 요청 | 폴더 목록 조회 | PC 내용 해시 계산 | PC 해시 재사용 | 복사 |
|---|---:|---:|---:|---:|---:|
| 기준 정보 최초 구축 | 457 | 455 | 2,070 | 0 | 0 |
| 변경 없는 반복 | 2 | 0 | 0 | 2,070 | 0 |
| PC 파일 10개 수정 | 72 | 10 | 10 | 2,060 | 10 |
| 앱이 올린 파일의 변경 기록 반영 | 12 | 10 | 0 | 2,070 | 0 |
| 다시 변경 없는 반복 | 2 | 0 | 0 | 2,070 | 0 |

위 수치는 합성 데이터의 요청 횟수이며 실제 Google Drive 전송 시간이나 속도 향상 배수를 뜻하지 않는다. 첫 전체 업로드에서 새 폴더를 많이 만들었다면 그 변경을 반영하기 위해 다음 실행에 전체 목록을 다시 구축할 수 있다. 폴더 구조 변경, 캐시 복구, 정기 검사와 삭제 전 소스 재검증도 의도적으로 전체 검사를 수행한다.

## 검증 범위와 재현

회귀 테스트는 변경 없는 재시작, 파일 수정·삭제·이동·생성, 폴더 이름 변경, 페이지 분할·반복, 잘못된 응답, 권한 오류, 취소, 손상·기한 경과, 필터·계정 분리, 검사 도중 변경 재생, 원격만 바뀐 파일 복구, 삭제 전 새 소스 검사를 포함한다. 독립 검토에서 발견한 변경 기록 범위와 손상 검사·파싱 문제를 수정했다.

```powershell
dotnet run --project tests/SimpleSync.Tests/SimpleSync.Tests.csproj -c Release
dotnet build -c Release --no-restore
```

비교 하네스는 Git 제외 경로 `artifacts/incremental-perf`에 있다. 실제 계정 데이터는 변경하지 않았으며 설치 파일은 생성하지 않는다.

공식 참고: [변경 추적](https://developers.google.com/workspace/drive/api/guides/manage-changes), [Changes API](https://developers.google.com/workspace/drive/api/reference/rest/v3/changes/list).
