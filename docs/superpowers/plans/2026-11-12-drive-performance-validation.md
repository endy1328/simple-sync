# simple sync 1.5.1 Drive 성능 검증

검증일: 2026-11-12

## 측정 조건

실제 계정 데이터는 변경하지 않고, 기존 Drive HTTP 테스트의 모의 서버와 실제 GoogleDriveEndpoint 구현을 연결했다. 454개의 직속 하위 폴더에 2,070개의 작은 .md 파일을 순환 배치했다. 파일 내용은 3바이트로 고정해 파일 내용보다 요청 횟수의 차이를 측정했다.

기준 구현은 최적화 전 1.5.0 소스의 보관본을 사용했다. 최초 실행은 전체 폴더 생성과 파일 업로드를 수행하고, 변경 없는 재실행은 목록 조회 및 폴더 준비를 수행한다. 기존 엔진의 불필요한 폴더 준비도 기준 측정에 포함했다.

쓰기 직전의 원격 이름 충돌 검사를 유지하기 위해 하위 항목 조회 횟수는 줄이지 않았다. 외부에서 새로 생긴 파일·폴더를 놓치는 캐시 기반 구현은 회귀 테스트에서 확인한 뒤 제거했다.

이 수치는 합성 데이터의 요청 횟수이며 실제 Google Drive 전송 시간을 뜻하지 않는다. 병렬 처리의 시간 단축 배수는 측정하지 않았다. 실제 시간은 파일 분포·폴더 깊이·네트워크와 API 제한에 따라 달라진다.

## 동작 검증

- 테스트 38개 그룹 통과: 기존 로컬·Drive·설정·UI 회귀와 새 병렬 처리 그룹.
- 최대 4개 상한, 양 끝점 중 더 작은 동시 처리 한도, Drive 소스와 타겟 양쪽의 병렬 처리 확인.
- 일반 소형 파일 사이의 Google 문서 내보내기는 앞뒤 병렬 작업과 겹치지 않도록 순차 장벽을 확인.
- 실패·취소 시 진행 중인 작업을 기다리고, 미러링 삭제를 생략하며, 완료 상태와 진행률을 일관되게 집계.
- 준비된 폴더의 재조회 감소, ID 묶음 예약, 같은 부모에 대한 24개 동시 쓰기, 중복 생성 방지 확인.
- 전송 중 원격 부모·상위 폴더·루트 변경, 뒤늦게 생성된 충돌 파일·폴더, 응답 유실, 해시 불일치, 대용량 재개 업로드 회귀 확인.
- 비동기 HTTP를 실제로 지연시키는 UI 테스트를 위해 STA 메시지 루프를 유지하도록 테스트 하네스를 보완.

설치 파일과 실제 클라우드 계정에 대한 성능 테스트는 수행하지 않았다.
