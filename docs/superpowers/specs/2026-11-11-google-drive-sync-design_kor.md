# simple sync 1.3.0 — Google Drive 동기화 설계

- 작성일: 2026-11-11
- 목표 앱 버전: **1.3.0**
- 설계 시작 시 앱 버전: 1.2.2
- 문서 상태: 구현 반영. 6절의 제안을 바탕으로 구현했으며 최종 선택과 검증 범위는 10절에 기록한다.

## 1. 목표와 버전 정책

기존 로컬 폴더 간 동기화를 유지하면서 개인 Google Drive와의 단방향 동기화를 추가한다. 기존 설정과 사용 흐름을 유지하는 기능 추가이므로 Semantic Versioning의 MINOR 버전인 1.3.0을 목표로 한다.

이 문서는 구현 완료나 배포를 의미하지 않는다. 설계 문서 작성 단계에서는 앱의 VERSION, 프로젝트 메타데이터, 설치 프로그램 버전을 변경하지 않는다. 기능 구현 완료 작업에서 실제 버전 관리 지점을 함께 1.3.0으로 갱신하고 CHANGELOG.md에 완료한 변경 사항과 날짜를 기록한다.

## 2. 확정된 기능 범위

| 항목 | 결정 |
|---|---|
| 지원 계정 | 개인 Google 계정 |
| 지원 저장 공간 | 내 드라이브 |
| 계정 수 | 여러 계정 연결, 동기화 쌍마다 계정 선택 |
| 방향 | PC → Drive 또는 Drive → PC |
| 모드 | 변경 파일 복사(copy), 미러링(mirror) |
| 덮어쓰기 | 소스 우선. 타겟이 더 최신이어도 내용이 다르면 소스를 반영 |
| 미러링 삭제 | 타겟에서 불필요한 항목을 휴지통 없이 영구 삭제 |
| 업로드 | 원래 파일 형식 유지. Office 파일을 Google 문서로 자동 변환하지 않음 |
| 다운로드 | 일반 파일 다운로드 및 Google 문서의 Office 형식 내보내기 |
| 기존 기능 | 로컬 → 로컬 동기화, 필터, 진행률, 로그 유지 |

Google 문서 내보내기의 기본 형식은 다음과 같다.

| 원본 | PC 저장 형식 |
|---|---|
| Google 문서 | Word .docx |
| Google 스프레드시트 | Excel .xlsx |
| Google 프레젠테이션 | PowerPoint .pptx |

양방향 동기화, 계정 간 Drive → Drive 전송, 회사·학교 계정과 조직 공유 드라이브 지원은 이번 범위에서 제외한다. 향후 연결 모듈을 확장할 수 있도록 구성한다.

## 3. 합의한 아키텍처

공통 동기화 엔진과 저장소별 연결 모듈을 분리한다. Drive 전용 엔진에 기존 로직을 복제하거나 외부 동기화 실행 파일을 의존성으로 추가하는 방식 대신, 비교·필터·작업 계획·상태 보고 규칙을 공유한다.

| 구성 요소 | 책임 | 주요 의존성 |
|---|---|---|
| 계정 관리 | 계정 연결·해제, 인증 갱신, 재로그인 상태 | Google OAuth, 암호화 토큰 저장소 |
| 동기화 쌍 설정 | 양 끝점, 모드, 필터, 활성 상태 저장 | 기존 설정 서비스 |
| 작업 계획기 | 목록 비교, 전송·덮어쓰기·삭제 계획 생성 | 저장소 목록, 필터, 상태 DB |
| 로컬 연결 모듈 | 로컬 목록 조회, 읽기·쓰기·영구 삭제 | Windows 파일 시스템 |
| Drive 연결 모듈 | 원격 조회·전송·영구 삭제·문서 내보내기 | Drive API, 계정 관리 |
| 실행기 | 계획 실행, 취소, 재시도, 진행률·오류 보고 | 작업 계획, 연결 모듈 |
| 상태 저장소 | Drive ID와 PC 경로 대응, 마지막 성공 상태 | 로컬 DB |

기존 Models.cs의 로컬 경로 중심 모델과 SyncService.cs의 파일 시스템 직접 접근을 위 경계에 맞게 확장한다. 기존 필터와 현지화 구조를 활용하며 관련 없는 리팩터링은 포함하지 않는다.

## 4. 합의한 계정·인증 설계

- 기본 웹 브라우저에서 Google OAuth 로그인을 진행한다.
- Desktop app 유형의 OAuth 클라이언트와 Authorization Code + PKCE, loopback 콜백을 사용한다.
- PC에서 Google에 직접 연결하며 별도 중계 서버를 두지 않는다.
- 계정별 인증 정보를 분리하고, 재실행 시 저장된 인증 정보로 연결을 유지한다.
- 인증 갱신이 실패하거나 접근 승인이 취소되면 해당 계정의 작업을 중단하고 재로그인 필요 상태를 표시한다. 다른 계정의 작업은 계속할 수 있다.
- 계정 제거 시 동기화 쌍을 보존하고 계정 연결 필요 상태로 둔다. 다른 계정으로 자동 대체하지 않는다.

기존 폴더 아래의 파일을 조회·다운로드·덮어쓰기·영구 삭제해야 하므로 `https://www.googleapis.com/auth/drive` 권한 범위를 사용하는 설계로 한다. 이 권한은 계정 전체에 대한 접근을 허용하지만 앱의 실제 작업 범위는 선택한 동기화 폴더 아래로 제한한다.

`drive.file`은 앱이 생성하거나 앱에 접근을 허용한 파일을 대상으로 하는 권한이다. 폴더 하나를 선택하면 기존 모든 하위 파일에 자동으로 접근할 수 있다고 가정하지 않는다. `drive`는 제한된 권한 범위이므로 공개 배포 준비에 OAuth 검증 요건 확인과 필요한 검증 절차를 포함한다.

## 5. 합의한 설정·상태 저장

| 정보 | 저장 위치·방식 |
|---|---|
| 방향, 모드, 필터, PC 경로, Drive 폴더 ID, 계정 참조 ID | config.toml 확장 |
| 계정별 인증 토큰 | 사용자별 앱 데이터 폴더, Windows 사용자 기준 암호화 |
| 파일 ID·상대 경로 대응 관계, 마지막 성공 상태 | 별도 로컬 상태 DB |

인증 토큰은 config.toml과 로그에 기록하지 않는다. 계정 식별은 안정적인 계정 식별자로 하고 이메일은 사용자 표시 용도로 사용한다. Drive 폴더 연결은 이름이나 표시 경로가 아닌 폴더 ID를 기준으로 유지한다.

기존 설정에서 저장소 종류가 생략된 Source와 Target은 로컬 경로로 해석한다. 구체적인 TOML 키 이름, DB 스키마 및 라이브러리 선택은 구현 계획에서 명시한다.

## 6. 상세 동작 제안 — 후속 검토 대상

이 절은 확정된 범위를 구체화하기 위한 제안이며, 사용자와 아직 개별 합의하지 않은 규칙이다.

### 6.1 실행 순서와 삭제 조건

1. 계정, 소스·타겟 폴더와 접근 권한을 확인한다.
2. 필터를 적용해 소스와 타겟 목록을 끝까지 조회한다.
3. 전송·덮어쓰기·삭제 작업 계획을 만든다.
4. 신규·변경 파일을 전송한다.
5. mirror 모드이고 조회·전송이 모두 성공한 경우에만 삭제를 실행한다.
6. 성공한 작업의 상태를 저장하고 결과를 표시한다.

소스 없음, 조회 실패, 페이지 조회 누락, 인증 오류, 전송 실패, 취소를 빈 소스로 해석하지 않는다. 실패한 실행에서는 미러링 삭제 단계에 진입하지 않는다. 정상적으로 조회된 빈 소스는 mirror 정책에 따라 타겟의 필터 대상 항목을 삭제할 수 있다.

필터 제외 항목은 복사와 삭제 대상 모두에서 제외한다. 폴더 재귀 삭제로 제외 파일까지 제거하지 않도록 파일 단위로 삭제하고, 삭제가 끝난 빈 폴더만 제거한다. Drive 영구 삭제 권한이 없는 항목은 실패로 보고하며 휴지통 이동으로 대체하지 않는다.

### 6.2 비교와 파일 대응

- 소스 우선은 타겟의 최신 수정 시각만을 이유로 전송을 생략하지 않는다는 의미다.
- 일반 파일은 크기·수정 정보와 사용 가능한 콘텐츠 체크섬을 활용해 비교한다. 동일성을 판정할 수 없으면 소스를 다시 전송한다.
- Google 문서는 원본 ID와 변경 정보, 내보내기 형식, 마지막 다운로드 상태를 기록해 변경 여부를 판단한다. 타겟 파일의 삭제·수정도 감지해 다시 반영한다.
- 이름 변경과 이동은 우선 새 위치에 소스를 반영한다. 이전 타겟 경로는 copy에서는 보존하고 mirror에서는 삭제 대상에 포함한다.
- 상태 DB가 없거나 손상된 경우 추정한 ID만으로 덮어쓰기·삭제하지 않고 전체 목록으로 대응 관계를 재구성한다. 모호한 항목은 오류로 처리한다.

### 6.3 이름 충돌과 지원하지 않는 항목

Drive는 같은 폴더 안에 같은 이름을 허용한다. Windows는 대소문자만 다른 이름, 일부 문자, 예약 이름에 제약이 있다. Google 문서 내보내기 후 일반 파일과 이름이 같아질 수도 있다.

자동으로 임의 파일을 선택해 덮어쓰는 대신, 충돌한 항목을 건너뛰고 원본 ID와 충돌 경로를 로그에 표시하는 정책을 제안한다. 충돌이 있는 실행은 미러링 삭제도 생략한다. 자동 이름 변환은 별도 합의 없이 추가하지 않는다.

첫 버전에서는 Drive 바로가기, 로컬 재분석 지점과 심볼릭 링크를 따라가지 않는 정책을 제안한다. Docs·Sheets·Slides 외의 Google 전용 형식은 미지원으로 표시한다. 의도적으로 제외된 항목과 오류로 읽지 못한 항목을 구분하고, 원본 항목이 있다고 알려진 경로를 단순한 부재로 처리해 타겟을 삭제하지 않는다.

### 6.4 전송·스케줄링·오류

- 다운로드는 임시 파일에 기록한 뒤 성공하면 타겟을 교체한다. 실패 시 기존 타겟을 보존한다.
- 업로드는 일반 파일 형식을 유지하고 대용량 파일에는 재개 가능한 업로드를 사용한다.
- 네트워크 일시 오류와 API 호출 제한은 제한된 횟수의 지수 백오프로 재시도한다. 권한 부족과 변환 불가는 반복 재시도하지 않는다.
- Google 문서 내보내기 실패 시 기존 PC 파일을 보존하고 실패를 보고한다. 표준 files.export의 변환 결과 10MB 제한을 반영한다.
- 자동 실행과 Sync Now가 겹쳐도 같은 쌍을 중복 실행하지 않는다. 끝점이 중첩되는 작업도 동시에 쓰거나 삭제하지 않도록 검증한다.
- Drive 조회 간격과 동시 전송 수는 로컬 동기화와 별도로 조절할 수 있도록 설계한다. 초기 기본값은 호출량과 실제 전송 검증 후 결정한다.

## 7. 검증 계획 제안

- 기존 로컬 copy·mirror, 필터, 설정 호환성 회귀 검증.
- 양쪽 방향의 신규 전송, 변경 반영, 소스 우선 덮어쓰기, 빈 폴더 처리.
- copy에서 삭제된 소스의 타겟 보존, mirror에서 영구 삭제.
- 조회·전송 실패와 취소 후 삭제 단계 생략, 필터 제외 항목 보존.
- 다중 계정 격리, 토큰 갱신, 연결 해제와 재로그인, 로그 내 인증 정보 누출 방지.
- Google 문서 3종 내보내기, 변경 후 재다운로드, 실패 시 기존 파일 보존.
- 중복 이름, 대소문자·Windows 이름 충돌, 변환 후 파일명 충돌.
- 재시작, DB 복구, 통신 단절, 호출 제한, 대용량 파일 및 업로드 응답 유실 후 중복 생성 방지.
- 실제 계정 검증은 전용 테스트 폴더를 사용하고, 영구 삭제는 테스트 데이터로 확인.
- 배포 시 VERSION, 프로젝트·앱 표시 버전, 설치 프로그램, 릴리스 노트와 CHANGELOG의 1.3.0 일치 확인.

## 8. 후속 설계 순서

1. 6절의 비교·충돌·미러링·지원 제외 규칙을 검토하고 확정한다.
2. 계정 관리와 동기화 쌍 편집 화면의 흐름을 확정한다.
3. 설정 스키마, 상태 DB, 연결 모듈 인터페이스와 단계별 구현 계획을 작성한다.
4. 구현·검증을 완료하고 1.3.0 버전 및 배포 문서를 함께 갱신한다.

## 10. 구현 반영 사항

- 모든 지원 방향을 공통 EndpointSyncService로 처리한다. 기존 로컬 엔진을 별도로 유지하지 않는다.
- 로컬 파일은 MD5로 내용을 비교하고 로컬 간 복사 시 원본 수정 시각을 보존한다. 동일 크기·수정 시각에 내용이 다른 파일도 감지한다.
- 내보내기 상태 저장소는 외부 DB 패키지 대신 계정·양 끝점으로 구분한 원자적 JSON 파일을 사용한다. 성공한 문서의 원본 ID·버전·타겟 해시를 저장한다.
- 구글 인증과 계정 저장은 GoogleAccountService, Drive 전송은 GoogleDriveEndpoint, 로컬 전송은 LocalStorageEndpoint에 분리했다.
- Drive 원본 문서는 Office 확장자를 매핑하고, Drive 타겟 조회는 원래 이름을 유지한다. 업로드 타겟이 Google 전용 문서이면 일반 파일로 직접 덮어쓰지 않고 형식 충돌로 보고한다.
- 자동 실행 간격은 1.3.0에서 기존 전역 설정을 공유한다. Drive 전용 간격과 사용자 조절 동시 전송 수는 이번에 추가하지 않았다. 작업은 순차 실행하며 일시적 API 오류는 제한된 백오프로 재시도한다.
- 필터에 포함된 미지원 원격 문서·바로가기와 로컬 링크는 실패로 처리해 미러링 삭제를 중단한다. 비어 있지 않은 타겟 폴더는 삭제하지 않는다.
- 계정·연결 설정 창을 여는 동안 자동 실행을 중지하고, 작업 중 동기화 쌍 편집을 차단한다. 동기화 중지 버튼으로 실행을 취소할 수 있다.
- 테스트는 로컬 파일, 모의 HTTP, 암호화 저장, STA 화면 검증으로 수행한다. 실제 Google 로그인·클라우드 전송 검증에는 OAuth 클라이언트 설정과 사용자의 브라우저 승인이 필요하다.
